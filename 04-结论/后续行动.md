# 🗓️ 后续行动

> 落地到日常 QA / 发布流程的行动清单。按阶段推进，每项打勾。

## 阶段一：环境与靶场（0.5–1 天）

- [ ] 安装 Docker Desktop（若未装）：<https://www.docker.com/products/docker-desktop/>
- [ ] 按 [[测试靶标搭建]] 启动 Juice Shop（`http://localhost:3000`）
- [ ] 按 [[测试靶标搭建]] 启动一个本地静态站（`python -m http.server 8888`）

## 阶段二：逐工具验证（按需 2–4 天）

- [ ] **Lighthouse**：按 [[01-Lighthouse#6 基本用法]] 对 `http://localhost:3000` 跑一遍，产出 HTML 报告
- [ ] **LinkChecker**：按 [[03-LinkChecker]] 方式 A（Docker）扫本地静态站，产出 CSV 报告
- [ ] **Wget/curl**：按 [[04-Wget-Spider]] 批量检查 URL 列表脚本
- [ ] **ZAP**：按 [[05-OWASP-ZAP#6 基本用法]] 对 Juice Shop 跑 `zap-baseline.py`，导出 HTML/JSON
- [ ] **Nikto**：按 [[06-Nikto#6 基本用法]] 对 Juice Shop 跑基础扫描，导出 JSON
- [ ] **WebPageTest**：注册免费 API key，用 CLI 测一个公网站点（本地靶场需内网穿透）
- [ ] **Screaming Frog**：下载安装，对本地静态站跑一次全站爬取（≤500 URL）
- [ ] 每项结果填入 [[测试记录模板]] 归档

## 阶段三：自动化接入（可选，1–2 天）

- [ ] **Lighthouse CI**：接入 CI，PR 自动跑分（`npx @lhci/cli autorun`），防止性能回退
  - 参考：<https://github.com/GoogleChrome/lighthouse-ci>
- [ ] **ZAP baseline**：接入 CI 每日定时跑被动扫描，告警归档
  - 参考：[[05-OWASP-ZAP#6 基本用法]] 的 Docker 命令
- [ ] **LinkChecker 定时巡检**：计划任务每周跑一次全站死链，发报告

## 阶段四：常态化

- [ ] 建立**月度性能/安全基线对比**（用归档的 [[测试记录模板]]）
- [ ] 重大发布前执行完整防线（[[选型建议#组合-3完整防线]]）
- [ ] 关注工具更新：ZAP 规则库、Nikto 数据库（`-update`）、Lighthouse 版本
- [ ] 评估 [[07-Screaming-Frog]] 付费版（若全站 URL > 500）
