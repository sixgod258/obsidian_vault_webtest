🛠️ 七大工具手册速览

每款工具的定位、安装要点与可行性结论（详见仓库「02-工具手册」各篇）。

01🚀 Lighthouse
Google 官方页面质量审计，无头 Chrome 五维打分（性能/可访问性/最佳实践/SEO/PWA），事实标准性能基准工具。
安装
npm install -g lighthouse
依赖
Node ≥ 20 + Chrome（本机已装 ✅）
特点
单页审计、报告直观、可接入 CI
局限
只测单页，实验室数据非真实用户
02🌐 WebPageTest
业界知名深度性能平台，真实浏览器 + 全球多节点 + 多种网速，核心杀手锏是资源加载瀑布图。
安装
网页直接用 或 npm install -g webpagetest
依赖
云端运行，本机零资源（需免费 API key）
特点
瀑布图 / Filmstrip / 多轮取均值
局限
测本机 localhost 需内网穿透；公共实例限量
03🔗 LinkChecker
免费开源死链检测器，递归爬取全站链接，检查 404/重定向/超时/SSL，多线程 + 多格式报告。
安装
Docker 推荐：ghcr.io/linkchecker/linkchecker
依赖
Python 3.10+ / Docker
特点
CSV/HTML/XML 报告、遵守 robots.txt
局限
大站爬取较慢；Windows 原生装需 WSL
04🕷️ Wget --spider
GNU Wget 爬虫模式：只检查链接有效性不下载内容，极轻量、零依赖、脚本友好。Windows 需用 wget.exe 或等价 curl.exe --spider。
安装
winget install JernejSimoncic.Wget
依赖
无（独立二进制）；本机 curl 零安装
特点
秒级判断、可批量、CI 冒烟测试
局限
无报告页面；对 JS 渲染页无效
05🛡️ OWASP ZAP
OWASP 官方 Web 应用安全扫描器（DAST），代理 + 爬虫 + 被动/主动扫描 + 模糊测试，可图形化也可 Docker 自动化接 CI。
安装
Docker 推荐：ghcr.io/zaproxy/zaproxy:stable
依赖
Docker（免 Java）或桌面版需 JDK 17+
特点
基线/主动/API 三套脚本；告警分级；HTML/JSON 报告
局限
主动扫描慢且耗资源、误报需研判、上手难
06🔍 Nikto
Web 服务器扫描器（Perl，8000+ 条检查）：危险文件、过期软件、配置错误、信息泄露。定位是快速侦察，与 ZAP 互补。
安装
Docker 推荐：ghcr.io/sullo/nikto
依赖
Docker（推荐）或 Perl
特点
几秒–几分钟极快；Tuning 分类 / -update 更新
局限
只扫服务器/已知模式；误报偏多；不隐身
07🐸 Screaming Frog SEO Spider
知名商业全站爬虫，输出每页 Title / Meta / H1 / 状态码 / Canonical / 重定向链 / 结构化数据等数十项 SEO 指标，可视化强。免费版限 500 URL 且不可导出。
安装
官网下载桌面版（GUI）；CLI 需付费授权
依赖
Java Runtime
特点
全站 SEO 审计、404/重定向排查、图表可视化
局限
商业软件；大站爬取吃内存；无人值守难

🔎 关键发现

从测试记录中提炼的、需要行动的核心问题（跨工具、跨维度）。

🚀 性能 —— 首屏核心问题是 JS 大包 + 布局偏移

  • 🔴 CLS = 0.903（达标 ≤0.1）—— 4 处布局偏移稳定复现，Lighthouse 性能分主要失分项（Lighthouse / perfeye）
  • 🔴 vendors.42aef419.async.js 打包 2.64MB / 未压缩 8.13MB，占 JS 下载量 89.5%，主线程阻塞 ~1.9s（WebPageTest + Lighthouse 交叉确认）
  • 🔴 静态资源无 Cache-Control，缓存评分 8/100，每次访问重新下载 3.2MB
  • 🟠 首屏白屏约 8s；HTTP/1.1 未启用 HTTP/2；DNS 解析 1064ms
  • 📌 建议：拆分 JS 首屏 < 500KB、加 hash 长缓存（max-age=31536000, immutable）、服务端 302 跳转鉴权、启用 HTTP/2

🛡️ 安全 —— 无高危，集中在配置类问题（修复成本低）

  • 🟠 ZAP 主动扫描：备份文件泄露 31 条（/ftp/quarantine* 下 .bak / - Copy / .zip）—— 最突出中危
  • 🟠 CORS Access-Control-Allow-Origin: * 跨域读取风险，应收敛白名单（ZAP + Nikto 均命中）
  • 🟠 缺失安全响应头：CSP / HSTS / COEP / COOP / Referrer-Policy
  • 🟠 敏感目录可访问：/ftp/encrypt.pyc、/ftp/package-lock.json.bak
  • 📌 结论：未发现可直接利用的 RCE / SQLi；ZAP 轻量化扫描深度浅，需放开 -m + 加 -j 现代蜘蛛才能更深层测

⚠️ 工具本身的实战经验

  • Nikto 对 SPA 误报率高：SPA 对未匹配路由统一返回 200，导致 140/152 条备份探测「全命中」→ 大概率误报，高危项必须人工复核
  • ZAP 主动扫描重资源：曾压垮 Docker 引擎（Java 堆 ~2GB），需用 -m 1 + 降线程 + 限容器资源轻量化；ascan.maxAlertsPerRule=20 疑似不生效
  • Docker 容器访问宿主机用 host.docker.internal，不能写 localhost
  • 测试环境污染：Chrome 扩展会污染 Lighthouse 数据，正式测试应使用无扩展环境或 Lighthouse CI
  • PowerShell 别名陷阱：wget/curl 是内置别名，须写 wget.exe/curl.exe

✅ 选型建议

按实际场景给出推荐组合，从「最小可用」到「完整防线」逐级加码。

🧩 组合 1 · 最小可用

Wget/curl + Lighthouse（本机已有）
curl 批量检查链接健康；Lighthouse 定期跑性能评分。零安装、零成本。
适合：个人开发者快速体检
推荐

🏷️ 组合 2 · 标准质检

LinkChecker + Lighthouse + ZAP（Docker）
LinkChecker 全站死链巡检；Lighthouse 发布前后性能对比；ZAP baseline 上线前安全基线。
适合：中小团队日常 QA

🛰️ 组合 3 · 完整防线

LinkChecker + Lighthouse + WebPageTest + ZAP + Nikto + Screaming Frog
链接 → 性能（快速+深度）→ 安全（应用+服务器）→ SEO 全站，分层执行。
适合：对质量有完整要求的产品/运维团队

🗓️ 后续行动路线图

落地到日常 QA / 发布流程的分阶段行动清单（当前全部 ⬜ 未开始）。

阶段一 · 环境与靶场 0.5–1 天

  • 安装 Docker Desktop
  • 启动 Juice Shop（http://localhost:3000）与本地静态站（python -m http.server 8888）

阶段二 · 逐工具验证 按需 2–4 天

  • Lighthouse / LinkChecker / Wget / ZAP baseline / Nikto / WebPageTest / Screaming Frog 逐一对靶场跑一遍
  • 每项结果按《测试记录模板》归档

阶段三 · 自动化接入 可选 1–2 天

  • Lighthouse CI：PR 自动跑分防止性能回退（npx @lhci/cli autorun）
  • ZAP baseline：CI 每日定时被动扫描，告警归档
  • LinkChecker 定时巡检：计划任务每周全站死链并发报告

阶段四 · 常态化

  • 建立月度性能/安全基线对比
  • 重大发布前执行完整防线（组合 3）
  • 关注工具更新：ZAP 规则库、Nikto 数据库、Lighthouse 版本
  • 评估 Screaming Frog 付费版（若全站 URL > 500）

🛡️ 合规提示

⚠️
安全工具（ZAP / Nikto）只对你有权扫描的目标使用。本仓库统一推荐使用本地靶场（Juice Shop / DVWA）验证流程，切勿对未授权的公网站点扫描——主动扫描会向目标发送真实攻击请求，可能触发 WAF 告警、写入日志、影响服务，并存在法律风险。
