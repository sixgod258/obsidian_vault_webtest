# Claude Code + Playwright 实现 Web 测试工具：可行性分析

> 结论先行：**7 款工具的核心功能大多可用 Claude Code 驱动 Playwright 实现**，且在对 SPA（如 Juice Shop）的某些检测上**比原工具更准**；无法替代的是 ZAP 的主动扫描深度与 Nikto 的 CVE 库。详细实测见各「实现记录」。

- 靶标：Juice Shop `http://localhost:3000`（本地授权）
- 方法：Claude Code 编写 Playwright 脚本 → 驱动真实 Chrome → 采集数据 → 生成 JSON → Claude 解读并写 MD 报告
- 实现脚本：`02-实现脚本/`（共享爬虫 `_lib.js` + 7 个工具脚本）
- 测试记录：`03-测试记录/`（7 份 + 原始数据 assets/）

## 一、可行性对比矩阵

| 工具 | 核心功能 | Playwright 实现度 | 关键做法 | 主要局限 |
|---|---|---|---|---|
| [[01-Lighthouse]] | 性能/SEO/可访问性评分 | ⭐⭐⭐⭐ | 注入 PerformanceObserver 采 LCP/CLS/INP/TTFB + DOM 检查清单 | 无 0–100 专有评分；INP 需交互 |
| [[02-WebPageTest]] | 瀑布图/电影胶片/时序 | ⭐⭐⭐⭐ | resource entries 采集瀑布数据 + 逐帧截图 | 无多地域节点 |
| [[03-LinkChecker]] | 全站死链检测 | ⭐⭐⭐⭐⭐ | SPA BFS 爬取 + request API 查状态 | 静态工具通病已在 SPA 上被 Playwright 补强 |
| [[04-Wget-Spider]] | 快速 URL 有效性 | ⭐⭐⭐⭐⭐ | 循环 request.get() 看状态码 | 与 wget 同样不渲染 JS |
| [[05-OWASP-ZAP]] | 安全漏洞扫描(DAST) | ⭐⭐⭐ | 被动扫描全实现（头/Cookie/泄露）+ 基础 XSS/SQLi 探测 | **主动扫描载荷深度不可替代** |
| [[06-Nikto]] | 服务器配置/已知漏洞 | ⭐⭐⭐ | 敏感路径探测 + 头指纹 + 目录列表 | 无 CVE/OSVDB 匹配库 |
| [[07-Screaming-Frog]] | 全站 SEO 审核 | ⭐⭐⭐⭐⭐ | 全站爬取 + 逐页 SEO 指标聚合 | 无商业可视化 |

> ⭐ 越多代表可实现度越高（⭐×5 = 完全实现，⭐×3 = 部分实现）。

## 二、每款工具：能不能做到？怎么做？

### 完全可实现（⭐×5）——链接与 SEO 类

**Wget --spider**：本质是"发请求看状态码"，Playwright `context.request.get()` 一行等价。脚本核心逻辑约 30 行（共 83 行，其余为 URL 清单与输出），20 个 URL 秒级出结果。→ 见 [[测试记录_2026-08-06_Playwright实现_WgetSpider_JuiceShop]]

**LinkChecker**：SPA 爬虫（读 `<a href>` + `[routerLink]`）→ 收集站内链接 → 逐个查状态。**在 SPA 上比原工具更强**：能发现客户端路由、能识别"软 404"（渲染判空）。→ 见 [[测试记录_2026-08-06_Playwright实现_LinkChecker_JuiceShop]]

**Screaming Frog**：同一套爬虫逐页提取 Title/Desc/H1/Canonical/alt/json-ld，再聚合缺失/重复问题。**免费、无 500 URL 上限、输出即结构化数据**，碾压免费版 SF。→ 见 [[测试记录_2026-08-06_Playwright实现_ScreamingFrog_JuiceShop]]

### 核心可实现（⭐×4）——性能类

**Lighthouse**：Web Vitals（LCP/CLS/TTFB）是同一批底层数据（Performance API），实测值可信；缺的是专有评分与 Best-Practices 全量规则。给"原始指标 + 阈值判定"信息量等价。→ 见 [[测试记录_2026-08-06_Playwright实现_Lighthouse_JuiceShop]]

**WebPageTest**：瀑布图（资源 start/end/type/size）+ 电影胶片（逐帧截图）+ 时序指标**全部能实现**，还能自绘 HTML 瀑布图；唯一做不了的是云端多地域节点。→ 见 [[测试记录_2026-08-06_Playwright实现_WebPageTest_JuiceShop]]

### 部分可实现（⭐×3）——安全类

**OWASP ZAP**：被动扫描（安全头/Cookie/信息泄露）几乎全实现，认证扫描反而比 ZAP 简单（先登录再扫）；**主动扫描只能做冒烟级探测**，替代不了 ZAP 的数百条攻击载荷规则。→ 见 [[测试记录_2026-08-06_Playwright实现_ZAP_JuiceShop]]

**Nikto**：敏感路径探测 + 响应头指纹 + 目录列表都能做；缺 Nikto 的核心资产——**CVE/OSVDB 版本匹配库**。→ 见 [[测试记录_2026-08-06_Playwright实现_Nikto_JuiceShop]]

## 三、Playwright 相比原工具的独特优势（实测发现）

1. **SPA 友好**：能爬客户端路由、能看渲染后 DOM——纯 HTTP 工具（wget/LinkChecker/Nikto）在 SPA 上有共同盲区：**所有未知路径都返回 200（index.html）**，产生海量假阳性。Playwright 可对比 index.html 壳签名剔除假阳性（Nikto 实现中 31/36 路径被正确识别为 catch-all）。
2. **软 404 / 死路由检测**：hash 路由服务器恒 200，静态工具无法区分；Playwright 可判定"路由是否渲染出内容"。
3. **认证测试简单**：登录态即浏览器状态，`storageState` 复用，安全扫描可带认证跑。
4. **CI 一体化**：脚本即数据即报告，一条命令出 JSON + MD，无需装 7 个工具。

## 四、共同局限

| 局限 | 说明 |
|---|---|
| 专有评分/规则库 | Lighthouse 评分、Nikto CVE 库、ZAP 攻击载荷——这些是各工具的核心资产，需引入对应审计库/漏洞数据才能补齐 |
| 环境依赖 | 需 Node + Chrome（本机已具备），比 wget/curl 重 |
| 云端能力 | WebPageTest 多地域节点等分布式能力无法本地实现 |
| 需要 Claude 参与 | "Claude Code 驱动"意味着每次要有人写/改脚本；纯无人值守仍需固化脚本 |

## 五、组合建议（结合本仓库 [[工具对比总表]] 的分层防御）

```
日常链接巡检  → 01-wget-spider.js + 02-linkchecker.js（秒级）
性能监控(CI)  → 04-lighthouse.js（Web Vitals 门禁）+ 05-webpagetest.js（瀑布诊断）
SEO 审核      → 03-screaming-frog.js（全站，免费无限量）
安全冒烟(CI)  → 07-zap.js（被动）+ 06-nikto.js（路径侦察）
上线前深度安全→ 仍用 ZAP 全量主动扫描（Playwright 实现不可替代）
```
