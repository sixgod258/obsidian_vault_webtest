# 🧪 测试方法论

> 怎么测、测几遍、怎么解读结果。写测试记录前先看这篇。

> 💻 **运行环境**：本文库所有命令默认为 **Windows PowerShell**（Windows 11 自带）语法。仅在 WSL / Linux 内执行的命令会用 `bash` 单独标注。

## 1. 测试前准备

1. **确定靶标**：新搭建的本地靶场见 [[测试靶标搭建]]；公网测试建议用 `https://example.com`。
2. **环境就绪**：确认各工具已按手册「安装指南」装好（`--version` 验证）。
3. **备份基线**：首测前记录系统状态（内存/网络），便于排除环境干扰。

## 2. 统一测试流程

每个工具的测试建议按固定节奏执行，结果才能横向对比：

```
① 冷启动基线测试（第一次访问，无缓存）
② 重复测试（二次访问，有缓存）
③ 修改/修复后复测
```

| 步骤 | 操作 | 目的 |
|---|---|---|
| 准备 | 关闭无关浏览器标签页，避免干扰 | 结果纯净 |
| 第 1 次 | 冷启动测一遍 | 拿到最差基线 |
| 第 2 次 | 相同参数再测 | 验证可复现性 |
| 取均值 | 多次结果取中位数 | 排除抖动 |
| 留档 | 结果截图/导出报告存入 `03-测试记录/` | 沉淀资产 |

## 3. 结果解读要点

### 性能类（Lighthouse / WebPageTest）
- **核心 Web Vitals**：LCP ≤ 2.5s / INP ≤ 200ms / CLS ≤ 0.1（绿色达标）。
- **评分 ≠ 真实体验**：Lighthouse 评分是"实验室数据"，移动端模拟；真实用户需 RUM 数据。
- **比较基准**：只和自己比（同配置、同时间窗），不要跨设备/跨网速直接比。

### 链接类（LinkChecker / Wget --spider）
- 关注 **HTTP 状态码**：404=彻底失效、403=访问受限（可能是权限而非死链）、301/302=重定向（可能需更新）。
- 死链判定前先确认**自己是否有访问权限**（如内网链接在公网扫描会误报）。

### 安全类（ZAP / Nikto）
- **告警分级**：Critical > High > Medium > Low > Informational，先处理高危，Info 级多需人工研判。
- **误报**：ZAP/Nikto 都有误报，高危告警务必人工验证后再提交修复。
- **仅限授权目标**：见 [[README]] 的合规提示。

## 4. 常见误区

| ❌ 误区 | ✅ 正确做法 |
|---|---|
| 只测一次就下结论 | 至少测 2 次取中位数 |
| 评分高=页面快 | 评分反映的是**指标**，实际体感看 LCP/INP 原始值 |
| 安全工具扫一遍没告警=安全 | 只能证明"已知规则没命中"，不是没有漏洞 |
| 用代理/VPN 测性能 | 会大幅污染结果，本地靶场应直连 |
| 拿安全工具扫未授权公网站点 | 法律风险，只测自己/授权的目标 |

## 5. 记录规范

每完成一轮测试，在 `03-测试记录/` 下按 [[测试记录模板]] 建一个文件，命名示例：

```
测试记录_2026-08-03_Lighthouse_本地靶场.md
测试记录_2026-08-03_ZAP_基线扫描.md
```

> 记录时附上：环境信息、命令原文、原始输出片段、关键结论、遗留问题。
