
## 3. 参数验证结论（重要）

- ✅ 确认执行了**主动扫描**（Backup File Disclosure 等主动规则带 attack 字段）
- ✅ `-m 1` 缩短爬虫生效（仅浅层爬取，多数规则 5 实例）
- ⚠️ `ascan.maxAlertsPerRule=20` **疑似未生效**：Backup File Disclosure 报了 31 条 > 20，需探针（`=3` 重跑）确认
- 📌 **扫描深度浅**：无 High、无 SQLi/XSS——因 1 分钟蜘蛛+低线程只爬到浅层，且 Juice Shop 漏洞接口为 JS 渲染需 `-j` 现代蜘蛛。**轻量化=省资源，但会漏检**

## 4. 结论与建议

- **未发现高危漏洞**，最突出中危是**备份文件泄露（31 条）**：清理 `/ftp/quarantine*` 目录下的备份/副本文件。
- 修复优先级：清理备份文件 → 收紧 CORS → 配置 CSP/COEP/COOP/HTTPS → 审查 `bypassSecurityTrustHtml`。
- 📌 **与基线记录结论差异说明**：同日 [[测试记录_2026-08-05_OWASP-ZAP_基线_本地靶场]]（基线扫描）侧重配置类问题（响应头缺失 / CORS 过宽），本记录（主动扫描）因把 `/ftp/quarantine*` 的备份文件扫出来了、首要问题偏"文件泄露"。**两者侧重不同、互为补充**，综合建议：先清理备份文件 + 收紧 CORS/CSP。
- 排查扫描期间的网络失败/慢响应/1342 条警告，确认服务稳定性。
- 若需真实找漏洞，需放开 `-m` 并加 `-j`（现代蜘蛛）重测。
